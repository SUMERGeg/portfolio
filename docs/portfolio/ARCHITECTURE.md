# Архитектура портфолио

Статус: дизайн-система, главная, галереи кейсов, внутренние страницы и взаимодействия реализованы; локальная приёмка завершена, публичный выпуск запланирован. Дата: 2 октября 2026 года.

## 1. Техническое направление

Выбранный стек: **Astro 7.3.5 + TypeScript + обычный CSS**. Для контентного портфолио со статическими кейсами этого достаточно: страницы собираются в HTML, интерактив добавляется только в нужных местах.

Приложение содержит девять страниц, общий layout, шапку/подвал, данные сайта и Markdown-коллекцию проектов. Главная использует `HeroProject`, `ProjectCard`, `HomeDetails`; список работ повторно использует `ProjectCard` с заголовком h2. Кейсы используют `CaseGallery` и реестр desktop/mobile пар `src/data/project-media.ts`. Astro Image создаёт WebP и адаптивные варианты локальных изображений. Стили карточек находятся в `project-card.css`, кейсов — в `case.css`, внутренних страниц — в `interior.css`. Перечень ниже также включает компоненты, которые могут появиться на следующих этапах.

Первая версия не требует CMS, базы данных, авторизации, React, глобального хранилища состояния или отдельной библиотеки анимаций. Не добавлять их без конкретной потребности.

## 2. Маршруты и навигация

| Маршрут | Содержание |
| --- | --- |
| `/` | Позиционирование, флагманский кейс, три проекта, услуги, процесс, об авторе, контактный CTA |
| `/work/` | Все три проекта с описанием роли и статуса |

Навигация: «Проекты» → `/work/`, «Услуги» → `/services/`, «Процесс» → `/#process`, «О себе» → `/about/`, «Контакты» и «Обсудить проект» → `/contact/`.

`Смотреть проект` в hero ведёт в локальный кейс NOIR. Внешняя демонстрация открывается отдельной явно подписанной ссылкой внутри кейса. Все внутренние маршруты должны работать при прямом открытии и обновлении страницы.

## 4. Данные проектов

Общий контракт записи:

- `slug`, `title`, `summary`, `category`;
- `status`: концептуальный проект или демоверсия;
- `demoUrl`: существующая внешняя демонстрация;
- `role`: подтверждённый вклад автора;
- `cover`: локальный файл, alt-текст, размеры и фокус кадрирования;
- `screens`: изображения, подписи и тип экрана;
- разделы кейса: задача, решения, структура, адаптивность, реализация и результат;
- `year` — необязательное поле, выводится только при подтверждении.

Страницы списка, hero и кейсы используют один источник метаданных. Описания кейсов хранить как Markdown с проверяемой схемой полей. Сведения о контактах отделить от текстов страниц; не размножать адреса по компонентам.

## 5. Рендеринг и взаимодействия

Основное содержание приходит в готовом HTML. Ссылки, проекты и контакты доступны без анимации и JavaScript.

- Мобильное меню: семантическая кнопка, состояние раскрытия, Escape, возврат фокуса.
- Hero: локальная иллюстрация ноутбука с экраном NOIR; вход и реакция на курсор добавлены поверх базовой композиции.
- Карточки: обычные ссылки с состояниями hover и focus, без обязательного hover для чтения.
- Галерея кейса: первоначально обычные изображения; модальное увеличение добавлять только при необходимости, с управлением фокусом.
- Переходы страниц: штатная навигация с нативным cross-document View Transition; участвует только выбранная обложка. При отсутствии поддержки остаётся обычный переход.

`src/scripts/motion.ts` использует Web Animations API и IntersectionObserver для однократных появлений; requestAnimationFrame вызывается только при движении мыши. `src/styles/motion.css` задаёт состояния и переходы. Классический скрипт в head общего layout связывает выбранные обложки до снимка страницы; ClientRouter и новые зависимости не добавлены.

При `prefers-reduced-motion` эффекты отключаются. На устройствах без точного указателя нет наклона hero; вход остаётся вертикальным. Не встраивать сайты проектов в iframe и не делать запросы к ним для рендеринга портфолио.

## 7. Медиа, SEO и производительность

- Референс хранится в документации и не включается целиком в сайт.
- Для hero и карточек подготовить изображения соответствующего размера, с фиксированными пропорциями и адаптивными версиями.
- Главный визуал загрузить приоритетно; изображения ниже первого экрана — отложенно.
- Самостоятельно размещать выбранные шрифты после проверки условий использования.
- У каждой страницы — полезные title/description; у кейса — собственное social-превью.
- Canonical, sitemap и robots формируются после выбора домена и пути публикации.
- Не публиковать исходные тяжёлые PNG-референсы как обычные карточки и не добавлять непрерывные графические эффекты.

## 8. Сборка и публикация

Предполагается статическая сборка. Площадка пока не выбрана. Если будет GitHub Pages с подпапкой, настроить базовый путь для ссылок, изображений и ресурсов; для размещения в корне домена использовать корневой путь.

Команды: `npm run dev` — разработка; `npm run check` — проверка типов; `npm run build` — статическая сборка в `dist/`; `npm run preview` — просмотр сборки. Проверка типов и сборка девяти страниц прошли на этапе 1.

На Windows официальный glob-loader загружается через `createRequire` в `src/content.config.ts`: это обходит ошибку определения CommonJS-зависимости в Astro 7/Vite 8. Метаданные и Markdown остаются в стандартной content collection Astro.

До готовности дизайна страницы имеют `noindex, nofollow`; окончательный домен и публичные SEO-настройки добавляются перед выпуском.

Перед публикацией проверить собранный результат: прямые URL, обновление страницы кейса, меню, контактные ссылки и изображения. Чек-лист находится в [QUALITY-GATES.md](QUALITY-GATES.md).
