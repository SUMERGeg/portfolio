# Анимации и взаимодействия — этап 5

Дата: 2 октября 2026 года. Этап выполнен. Пользователь попросил немного вау-эффекта и более заметное движение.

## Что реализовано

| Элемент | Поведение |
| --- | --- |
| Первый экран | Текст появляется последовательно с шагом 75 ms; ноутбук входит за 1100 ms из уменьшенного состояния с глубиной |
| Ноутбук и свет | На desktop с мышью устройство наклоняется до 5° по горизонтали / 3° по вертикали и смещается до 10 / 6 px; свет движется в противоположную сторону |
| Карточки | Подъём, небольшой наклон, приближение изображения и поворот стрелки; отдельное состояние клавиатурного фокуса |
| Открытие кейса | Выбранная обложка переходит из карточки в изображение кейса и обратно за 620 ms; остальные проекты не участвуют |
| Секции | Однократное появление при входе в область просмотра за 760 ms |
| CTA | Подъём и проходящий блик при наведении; короткое нажатие на touch |

## Устройство и ограничения

`src/scripts/motion.ts` — небольшой модуль Web Animations API + IntersectionObserver. Базовый HTML/CSS видим без него. Появления добавляются только при наблюдаемом входе секции; клавиатурный фокус отменяет её активную анимацию. Непрерывного цикла кадров нет: requestAnimationFrame запускается по движению мыши. При уходе со страницы, потере фокуса и скрытии вкладки эффекты останавливаются или сбрасываются.

`src/styles/motion.css` — переходы страниц и состояния компонентов. Классический скрипт в head `SiteLayout.astro` назначает имя только выбранной обложке на время снимка перехода и затем очищает его. Ссылки и история остаются штатными; новых зависимостей и клиентского роутера нет. Механизм использует [официально описанные cross-document View Transitions](https://developer.chrome.com/docs/web-platform/view-transitions/cross-document); при отсутствии поддержки работает обычная навигация.

На touch и ширинах меньше 900 px нет реакции на указатель, ноутбук появляется без бокового смещения. `prefers-reduced-motion: reduce` отключает появления, наклон, hover-анимации и переходы страниц, включая изменение настройки во время открытой страницы. Прокрутка не перехватывается, свет не пульсирует непрерывно.

## Проверка

- `npm run check`: 23 файла, 0 ошибок / 0 warnings, две информационные подсказки.
- `npm run build`: девять страниц, 61 оптимизированное изображение, успешное завершение.
- Браузер: отсутствие горизонтального переполнения **во время входа ноутбука** на 1440/1024/768/390; наклон и сброс при уходе курсора; переход NOIR вперёд и назад с анимацией только его обложки; появление секции при прокрутке и видимый клавиатурный фокус. Ошибок браузера нет.
- Отдельный сценарий фактического motion-скрипта: reduced-motion при старте и изменении настройки, отмена анимации при фокусе, очистка pointer/observer при уходе, вертикальный вход на touch.
- [Измерения и результаты](media/stage5-motion-checks.json), [снимок главной](media/stage5-home-1440.jpg).

Настройка reduced-motion ОС не эмулировалась в браузере; её логика проверена сценарием скрипта и правилами CSS. Браузерный сеанс с отключённым JavaScript не проводился; видимость базового содержания проверена по реализации. Полная приёмка сайта остаётся этапом 6.
